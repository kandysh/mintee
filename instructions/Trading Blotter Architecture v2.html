TanStack Router's loader runs the workspace fetch before the component mounts. No loading spinner on route change — data arrives with the route.
URL as filter source of truth
?instrument=AAPL&desk=FX&from=2024-01-01

TanStack Router v1 has first-class validateSearch with Zod — filters are typed, validated, and shareable. On mount, Zustand filterStore initialises from URL params. Filter changes update URL via router.navigate (replaceState, not push — no history spam).
Route loader pattern
The loader calls queryClient.ensureQueryData(workspaceQuery(id)) — TanStack Query handles caching, so navigating back to a workspace is instant if the cache is warm. No waterfall between route and first render.

Why Dockview over Golden Layout
Zero runtime dependencies. React-first API — no manual portal management or React root lifecycle handling. TypeScript-native. Active maintenance with frequent releases. Floating panels and popout windows built in.

Golden Layout's React integration in v2 requires you to manage React portals manually — every panel is rendered into a GL-owned DOM node. Dockview handles this internally, your components just render normally.
Panel registry pattern
const components = {
  blotter: BlotterPanel,
  chart: ChartPanel,
  'ai-html': AiHtmlPanel,
}

Pass to <DockviewReact components={components}/>. Each panel type is self-contained — it knows its own filter subscriptions, data needs, and config shape. Adding a new panel type = one file + one registry entry.
Serialization flow
Dockview exposes api.toJSON() — returns a plain JSON object representing the full layout. On any layout change event → write to layoutStore.pendingLayout, set isDirty=true.

Save → POST to BE → isDirty=false
Reset → fetch saved layout → api.fromJSON(savedLayout)
Critical for a trading app
Users keep this workspace open all day. One broken AI-generated widget must not take down the whole layout. Wrap every panel render in a React ErrorBoundary — show a fallback tile with a reload button. This is non-negotiable.

Zustand v5 change that matters
useShallow is now a first-class export. For filter subscriptions in panels use useFilterStore(useShallow(s => ({ inst: s.instrument, desk: s.desk }))) — only re-renders when those specific values change. Critical at 20K rows.
layoutStore
Tracks pendingLayout (unsaved Dockview JSON) and isDirty (drives Save button state). On Dockview's onDidLayoutChange event → update store. Save mutation success → reset isDirty.
One WebSocket, not one per panel
wsStore owns the single WS connection. All panels read from it — never create panel-level WS connections.

16ms batch buffer: accumulate deltas for one animation frame, flush to AG Grid via applyServerSideTransaction in one call. Without batching, 50 ticks/sec will saturate renders.

wsStore also handles: reconnect with exponential backoff, heartbeat ping/pong, stale-data indicator on disconnect.
useWorkspace(id)
Fetches saved layout JSON. Pre-fetched in route loader so it's cache-warm before component mounts. Result hydrates api.fromJSON() on Dockview ready event.
TanStack Query is NOT in the live data path
It's request/response — not built for high-frequency WS streams. Use it for the initial AG Grid SSRM data source. After that, live deltas come through wsStore directly to AG Grid's transaction API.
useSaveLayout mutation
POSTs serialised Dockview JSON to POST /workspaces/:id/layout. On error → toast, keep isDirty=true for retry. On success → invalidate useWorkspace query so it's fresh on next load.

AG Grid v33 — what's changed
AG Grid v33 introduced a State API (gridApi.getState() / applyState()) that serialises column state, filter state, and sort state in one call. Use this instead of manually tracking column config — it integrates cleanly with your panel config serialization in Dockview's toJSON.

Still use SSRM for 20K rows. Client-side mode at that scale + live WS updates will block the main thread.
ChartPanel
Wrap your existing chart component from the asset library. The panel subscribes to filterStore.instrument and requests OHLCV data through TanStack Query. For real-time chart updates, pipe WS ticks directly — don't go through TQ.
Security — non-negotiable
<iframe sandbox="allow-scripts" srcdoc={sanitizedHtml}/>

The sandbox blocks: DOM access to parent, localStorage, cookies, navigation, form submission. Never use dangerouslySetInnerHTML for LLM output in a fintech app. Also tell BE: sanitize HTML server-side before storing — don't trust the client to always sandbox correctly.
Panel config drawer
Each panel type exports a ConfigPanel component — rendered in a slide-out drawer when the user clicks a settings icon in the panel header. Dockview supports custom header actions natively. Config changes update panel.params via Dockview's panel API, which triggers onDidLayoutChange → persisted with the layout.

WsManager — singleton created on app mount, held in wsStore.

Responsibilities: exponential backoff reconnect, heartbeat ping/pong (detect silent disconnects), message type routing to correct store slice, stale data banner when connection drops.

Send filter subscriptions through same socket so server filters data: { type: 'SUBSCRIBE', filters: { desk: 'FX' } } — never filter 20K delta messages client-side.
HTTP client
Use ky (modern fetch wrapper, smaller than axios, tree-shakeable). Thin wrapper adds auth header injection and 401 redirect. All TanStack Query hooks use this — no raw fetch in components.
Contracts to lock down with BE in week 1:
GET /workspaces/:id — load saved layout JSON
POST /workspaces/:id/layout — save layout JSON
WS delta: { type: 'TRADE_UPDATE', payload: { id, ...fields } }
WS delta: { type: 'TRADE_NEW', payload: { ...trade } }
WS sub: { type: 'SUBSCRIBE', filters: {...} }

Changing WS message shape after FE integration starts = a week of wasted work. Lock this first.
